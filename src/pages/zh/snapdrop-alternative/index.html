RealtimeClipboard / Snapdrop 替代方案

仍然好用的 Snapdrop 替代方案

最直接的平替是 PairDrop —— 它是社区从 Snapdrop 自己的源码分出来的分支，用法和当年的 Snapdrop 一样， 而且不同于原版，它还能给不在同一个网络里的设备配对。如果你真正想做的 是复制粘贴而不是传文件，那么像这样的浏览器剪贴板比它们俩都更合适。

Snapdrop 后来怎么了

Snapdrop 是 Robin Linus 做的一个单页网站：在同一个 Wi-Fi 下的两台设备上 打开它，它们就能互相看见，你把文件拖过去就行。不用账号，不用装应用，不用 配置。它好用到多年来一直是大家默认推荐的那一个。

原来的项目仍然挂在 GitHub 上，许可证也没变，但 snapdrop.net 这个域名换了主人，如今在那里应答的站点是商业运营的，不再由原作者维护。 老用户几乎都是先觉得行为不对劲，之后才知道东家已经换了 —— 所以来到这个 页面的人，说出口的通常是症状，而不是原因。

不过下面的内容并不依赖这段往事。每一个选项都免费、都开源，每一条说法你都 能对着它自己的仓库核实一遍 —— 当一个你天天依赖的工具悄悄变成另一个工具时， 能核实才是最要紧的那件事。

几个替代方案的对比

PairDrop、LocalSend、RealtimeClipboard、Wormhole 和 KDE Connect 的 对比：要不要账号、要不要安装、能不能跨不同的网络工作、管不管系统 剪贴板，以及文件大小上限。

该挑哪一个

给同一个房间里的人传一个大文件 —— 用 LocalSend。它是原生应用而不是 网页，所以不受浏览器那些限制，在局域网里也是这几个里最稳的一个。

要 Snapdrop 那一套用法，而且还在浏览器里 —— 用 PairDrop。界面一脉 相承，依然免费，而六位配对码意味着两台设备不必再连同一个 Wi-Fi。这是最 直接的平替。

在自己的几台设备之间搬文字、链接、验证码和密码 —— 这恰恰是传文件的 工具全都别扭起来的地方。PairDrop 能发文字，但它到了那头是一条消息，你还得 手动选中再复制一次。大多数人真正想要的，是那段文字在另一头已经躺在 剪贴板上，抬手就能粘。

RealtimeClipboard 合适做什么，不合适做什么

它就是剪贴板，不是一条消息
在这台设备上复制，切到另一台粘贴。没有什么要先选中的。
不在同一个网络也没关系
家里的 Wi-Fi 和手机流量之间照样通。两台设备不必挨在一起。
文件上限 5 MB
要传一段视频，请改用 LocalSend 或 PairDrop。这件事它不合适。
自动读取需要 Chromium 内核
Firefox 和 Safari 能发送和接收你粘贴进来的文字，但不能自己读剪贴板。
密钥就是密码
谁知道它，谁就能读这个会话。涉及敏感内容，就用 PIN 码把它锁上。

三步就能用起来

  1. 在第一台设备上打开它，它会生成一个短密钥。
  2. 在第二台设备上输入这个密钥，或者扫一下二维码。
  3. 随便复制点什么。切到另一台设备粘贴 —— 它已经在那儿了。

文字在你的浏览器里先用 AES-GCM 做端到端加密再发出去，中继服务器按密钥的 哈希值而不是密钥本身来路由，所以服务器手上从来没有读得懂的东西，也什么 都不存。文件走 WebRTC 在两个浏览器之间直连，根本不经过它。要是你更愿意 自己读代码而不是听人保证， 源码在 GitHub 上， 用的是 MIT 许可证。

常见问题

Snapdrop 现在还能放心用吗？

原来那份开源代码没有变，你依然可以自己部署一份。大家担心的是老域名上 托管着的那个站点 —— 它现在由与作者无关的另一方商业运营。如果你要的是 原本的用法，同时又想背后有一个还在维护的社区项目，那就用 PairDrop 这个分支。

PairDrop 和 Snapdrop 是一回事吗？

PairDrop 最初就是 Snapdrop 的一个分支，核心思路一点没改 —— 两台设备打开 同一个页面，不用账号就能互传。它多了六位配对码和公开房间，这正是它能在 不同网络的设备之间工作的原因。Snapdrop 自己从头到尾只做局域网发现。

只传文字而不是文件，最好的 Snapdrop 替代方案是什么？

是在线剪贴板，而不是传文件的工具。差别在于那段文字最后落在哪里：传输 工具把它当成一条消息交给你，你还得手动复制一次；在线剪贴板则是把它放进 接收设备的系统剪贴板，你可以直接粘进手头正在做的事情里。 RealtimeClipboard 做的就是这件事。

这些工具里有能跨不同 Wi-Fi 网络用的吗？

PairDrop、Wormhole 和 RealtimeClipboard 可以。LocalSend、KDE Connect 和原版 Snapdrop 在设计上就只支持同一个局域网里的设备 —— 它们靠在同一个 子网里广播来互相发现。更详细的说明在 跨不同网络的剪贴板同步。

这些都免费吗，要不要注册账号？

上面表里的每一个都免费，也都不需要账号。PairDrop、LocalSend、KDE Connect 和 RealtimeClipboard 都是开源的，所以如果你不愿意指望别人的服务器一直 保持原样，完全可以自己架一份。
