装上它

桌面 —— Windows、macOS、Linux

桌面应用是给同一个页面套了个窗口，再加一个盯着系统剪贴板的小小原生助手。 那个助手就是它存在的理由：在任何程序里复制，你还没切过去，内容已经在你 别的设备上了。

它开着的时候，你每一次复制它都读得到。你装的就是这个。它从不把任何 内容写到磁盘上，离开这台机器之前也已经加密 —— 但如果你更希望它只发你挑 出来的内容，就在设置里把它切到应用内。

这些构建还没有做代码签名，你的电脑会这么告诉你。Windows 会弹出 “Windows 已保护你的电脑” —— 点更多信息 → 仍要运行。macOS 会拒绝 第一次启动；打开系统设置 → 隐私与安全性，再点仍要打开。 这两个都不代表文件坏了：证书要按年付钱，这个项目没有买，所以除了发布页 上的校验和、以及你可以把每一行源码读完这件事，没有别的东西为这个二进制 文件作保。

Android、iPhone 和 iPad

没有 App 要装，而这是想清楚之后的决定，不是缺口。两个平台都不允许任何 应用在后台读取剪贴板 —— Android 从版本 10 起就收紧了，iOS 则从来 没放开过。所以一个原生应用能多给你的，只有一个分享菜单按钮和一条商店 条目，除此之外没有一件事是你正读着这段话的页面做不到的。

所以，把它添加到主屏幕就好。它会有自己的图标和窗口，离线也能用。

命令行 · 进阶

从终端安装

同样的构建，交给你本来就信任、也愿意让它替你更新的包管理器 —— 另外， 给完全没有桌面的机器备了一个只有管道、没有窗口的客户端。

包管理器

两个，而且只在它们真的可用之后才写在这里。每一个都是 tools/release/manifest.mjs 从发布产物生成的清单，之后还得 由别人审核并合并 —— 所以命令上的标签说它能用，它才能用，不会提前。

Windows —— winget

审核中 
winget install AkshayNikhare.RealtimeClipboard

0.3.0 的清单已经提交， 正在等微软的审核，这件事按天算而不是按分钟算。合并的那一刻这条命令 就开始生效，在那之前不会。 Windows 包管理说明

macOS —— Homebrew

brew install --cask akshaynikhare/tap/realtimeclipboard

这个 cask 装的就是上面那个按钮给你的通用构建，用 brew upgrade 更新。它还会去掉隔离标记，所以手动下载 要跳的那段 Gatekeeper 舞步可以省了。 macOS 包管理说明

Linux —— 没有

没有 Flathub、Snap 或 AUR 包，这里也不摆一条假装有的命令。用上面的 .deb、.rpm 或 AppImage；每一个都是单独一个 文件，谁也不需要仓库。 Linux 包管理说明

在你的浏览器里

一个弹窗加两个快捷键，用来在不打开应用的情况下把你复制的东西发出去。它 不在商店里：每次发布都会带上一个 zip，Chrome 从文件夹里加载它。

Chrome、Edge、Brave —— 加载已解压的扩展

# 1. 从上面的发布页取 realtimeclipboard-browser-<version>.zip
# 2. 解压到一个你会长期留着的位置
# 3. chrome://extensions -> 开发者模式 -> 加载已解压的扩展程序 -> 选那个文件夹

文件夹要留着：浏览器每次启动都会去读它，所以随手清空的下载目录是个 错误的家。这种方式没有自动更新，Chrome 还会偶尔问你是不是真要留着 一个开发者模式的扩展。这里没有一键安装程序，因为没有哪次发布带 .crx —— 而且在 Windows 和 macOS 上，Chrome 本来也会 拒绝一个来自它自家商店之外的包。 最新发布

只限 Chromium 内核 —— Chrome、Edge、Brave、Opera、Arc。Firefox 不行： 剪贴板桥接需要一个 Firefox 没有实现的 API。而且它在任何浏览器上都不做 后台同步，那正是桌面应用和编辑器扩展要干的活。

服务器、SSH 和脚本

一个命令行客户端，给那些根本没有剪贴板的机器用。它说的是和浏览器一样的 协议、一样的加密 —— 它导入的就是同一批文件 —— 所以从服务器发出的一条 剪贴内容，和别的没有任何两样地出现在你的笔记本上。 

npx realtimeclipboard D75LV

它是干什么用的

# 把东西管道进来
echo "deploy key" | npx realtimeclipboard send D75LV

# 接住下一条剪贴内容然后退出
npx realtimeclipboard watch D75LV --once > token.txt

# 从一台你 ssh 上去的机器
ssh build-01 'cat /var/log/deploy.log' | npx realtimeclipboard send D75LV

需要 Node 22 或更新的版本，而且什么都不用装：npx 会按需去拉。 命令行指南 →

自己跑一个中继服务器

中继服务器在设备之间搬运加密后的剪贴内容。它除了房间哈希和密文之外什么 也看不到，也什么都不存 —— 但你不必只凭信任，因为你可以自己跑一个。它就 是一个 Python 文件，没有数据库。 

docker run -p 8000:8000 ghcr.io/akshaynikhare/realtimeclipboard-relay

或者从源码跑

pip install -r backend/requirements.txt
python -m uvicorn main:app --app-dir backend --port 8000

要 TLS 和一个真实域名就用 deploy/docker-compose.yml， 旁边还放着一份 Helm chart。然后在应用里把中继服务器指过去： 设置 → 中继服务器。 自建部署指南 →
