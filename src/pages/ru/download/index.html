Скачать RealtimeClipboard

Ничего из этого вам не нужно. RealtimeClipboard работает во вкладке браузера на каждом вашем устройстве, и это и есть весь продукт. Настольное приложение добавляет ровно одну вещь, на которую браузер не способен в принципе: оно замечает, что вы копируете, пока вы работаете в другом месте.

Один клик · без терминала

Установите

Скачайте, откройте, готово. Выберите машину, за которой сидите.

Компьютер — Windows, macOS, Linux

Настольное приложение — это окно вокруг той же самой страницы плюс маленький нативный помощник, который следит за системным буфером обмена. Ради этого помощника оно и существует: копируете в любой программе — и текст уже на других ваших устройствах, ещё до того как вы к ним переключитесь.

Пока оно запущено, оно читает всё, что вы копируете. Именно это вы и устанавливаете. Оно ничего не пишет на диск, и содержимое шифруется до того, как покинет машину, — но если вам спокойнее, чтобы уходило только выбранное вами, переключите его в настройках на Приложение.

Windows покажет «Система Windows защитила ваш компьютер» — выберите Подробнее → Выполнить в любом случае. macOS откажет в первом запуске; откройте Системные настройки → Конфиденциальность и безопасность и нажмите Всё равно открыть. Ни то, ни другое не значит, что файл повреждён: сертификат стоит денег каждый год, и этот проект его не покупал, так что за двоичный файл не ручается ничто, кроме контрольной суммы на странице релиза и того, что вы можете прочитать каждую строчку, которая в него вошла.

Android, iPhone и iPad

Устанавливать нечего, и это осознанное решение, а не пробел. Ни одна из двух платформ не позволяет приложению читать буфер обмена в фоне — Android ограничил это в десятой версии, а iOS не разрешала никогда. Нативное приложение поэтому могло бы дать кнопку в меню «Поделиться» и карточку в магазине — и ничего сверх того, чего не умеет страница, на которой вы это читаете.

Поэтому просто добавьте её на главный экран. У неё будет свой значок и своё окно, и она работает офлайн.

Установка из терминала

Те же сборки, но из пакетного менеджера, которому вы и так доверяете их обновление, — и, для машин вообще без рабочего стола, клиент, который весь состоит из труб и не имеет окна.

Пакетные менеджеры

Два, и только после того, как они станут настоящими. Каждый из них — манифест, который tools/release/manifest.mjs собирает из релиза и который потом кто-то другой должен проверить и влить, так что команда работает тогда, когда об этом говорит метка рядом с ней, и не раньше.

Windows — winget

на проверке 
winget install AkshayNikhare.RealtimeClipboard

Манифест 0.3.0 отправлен и ждёт рецензентов Microsoft, а это дни, а не минуты. Эта команда начнёт работать в тот момент, когда его вольют, и не раньше. О пакете для Windows

macOS — Homebrew

brew install --cask akshaynikhare/tap/realtimeclipboard

Cask ставит ту же универсальную сборку, что выдаёт кнопка выше, и обновляется через brew upgrade. Он ещё и снимает метку карантина, так что танец с Gatekeeper, обязательный при ручной загрузке, вы пропускаете. О пакете для macOS

Linux — никаких

Ни Flathub, ни Snap, ни AUR, и здесь нет команды, которая делала бы вид, что они есть. Возьмите .deb, .rpm или AppImage выше: каждый из них — один файл, и репозиторий не нужен ни одному. О пакетах для Linux

Внутри редактора

В браузере

Всплывающее окно и два сочетания клавиш, чтобы отправить скопированное, не открывая приложение. В магазине его нет: сборка едет с каждым релизом в виде zip, и Chrome загружает её из папки.

Chrome, Edge, Brave — загрузка распакованного расширения

# 1. возьмите realtimeclipboard-browser-<version>.zip из релиза выше
# 2. распакуйте туда, где оставите насовсем
# 3. chrome://extensions -> Режим разработчика -> Загрузить распакованное расширение -> выберите папку

Папку сохраните: браузер читает её при каждом запуске, так что папка загрузок, которую вы очищаете, — неподходящий дом. Автообновления при таком способе нет, и Chrome будет иногда спрашивать, точно ли вы хотели оставить расширение в режиме разработчика. Установки в один клик нет, потому что ни один релиз не выпускает .crx — да и на Windows и macOS Chrome всё равно отказался бы принять его извне своего магазина. Последний релиз

Только Chromium — Chrome, Edge, Brave, Opera, Arc. Firefox не подойдёт: мосту с буфером обмена нужен API, которого Firefox не реализует. И ни в одном браузере расширение не синхронизирует в фоне — для этого есть настольное приложение и расширение для редактора.

Серверы, SSH и скрипты

Клиент командной строки для машин, у которых буфера обмена нет вовсе. Он говорит на том же протоколе и с тем же шифрованием, что и браузер, — он импортирует ровно те же файлы, — поэтому фрагмент, отправленный с сервера, появляется на ноутбуке как любой другой. 

npx realtimeclipboard D75LV

Для чего он нужен

# отправить что-нибудь по трубе
echo "deploy key" | npx realtimeclipboard send D75LV

# взять следующий фрагмент и выйти
npx realtimeclipboard watch D75LV --once > token.txt

# с машины, куда вы зашли по ssh
ssh build-01 'cat /var/log/deploy.log' | npx realtimeclipboard send D75LV

Нужен Node 22 или новее, и ничего не устанавливается: npx подтягивает по требованию. Руководство по командной строке →

Свой ретранслятор

Ретранслятор переносит зашифрованные фрагменты между устройствами. Он не видит ничего, кроме хеша комнаты и шифротекста, и ничего не хранит — но верить на слово не обязательно, потому что вы можете поднять его сами. Это один файл на Python без всякой базы данных. 

docker run -p 8000:8000 ghcr.io/akshaynikhare/realtimeclipboard-relay

Или из исходников

pip install -r backend/requirements.txt
python -m uvicorn main:app --app-dir backend --port 8000

Для TLS и настоящего домена возьмите deploy/docker-compose.yml, рядом лежит и Helm chart. Потом укажите приложению свой ретранслятор в разделе Настройки → Ретранслятор. Как поднять свой ретранслятор →
