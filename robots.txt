# This file is live. It was not, for the whole life of the project before now.

#
# robots.txt is only read at the ROOT of an origin. The site used to deploy to
# https://akshaynikhare.github.io/RealtimeClipboard/ , which put this file in a
# subdirectory where no crawler would ever fetch it — the file that actually
# governed that origin lived in a different repository, so the sitemap below
# could not be declared from here at all and nothing had ever told a crawler it
# existed.
#
# Since the move to https://realtimeclipboard.com/ this file sits at an apex and
# is authoritative. Which also means a mistake in it is now capable of doing
# real damage rather than none: tools/site-check.mjs asserts the Sitemap line
# points at the canonical origin, and fails the deploy if it does not.
#
# ---------------------------------------------------------------------------
# Why there is no longer a Disallow for the app
# ---------------------------------------------------------------------------
#
# The app answers at /app. The file behind it is still app.html — Cloudflare
# serves any .html asset at its extensionless path — so both spellings reach
# the same page, and a Disallow would have had to name both to mean anything.
#
# The previous version blocked it, and the reasoning was backwards. A page
# blocked by robots.txt is never fetched, so its noindex is never read, and
# Google stays free to list the bare URL on the strength of the links pointing
# at it. The landing page links to /app three times. Blocking is how you get
# the app indexed as a naked URL, not how you keep it out.
#
# /app carries `noindex, nofollow, noarchive, nosnippet, noimageindex`.
# Letting crawlers fetch it is exactly what makes that tag work.
#
# There is also nothing there to protect. The session key lives in the URL
# fragment, which is never sent to a server and is not a distinct URL to a
# crawler. Googlebot rendering /app gets an empty app with no key in it.

# ---------------------------------------------------------------------------
# Answer engines
# ---------------------------------------------------------------------------
#
# The wildcard group below already allows every one of these. They are named
# anyway because the failure they guard against is someone adding a Disallow
# later "for the AI scrapers" and taking the citation crawlers out with it —
# these are the bots that decide whether the site appears in a ChatGPT,
# Perplexity or Copilot answer, and they are not the ones that train models.
#
#   OAI-SearchBot    ChatGPT's citation crawler. Blocking it removes the site
#                    from ChatGPT answers outright. GPTBot is the training
#                    crawler and is a separate decision.
#   Claude-SearchBot / PerplexityBot   the same role at Anthropic and Perplexity.
#   *-User           fetches made because a person asked, not crawls.
#   bingbot          serves Bing, and Bing's index is what Copilot grounds on.
#                    Also the only one of these reachable from mainland China,
#                    via cn.bing.com.
#   DuckAssistBot    DuckDuckGo's AI answers, which cite back. DuckDuckGo is a
#                    real referrer in the analytics, so this one is not
#                    hypothetical.
#   Applebot         Siri and Spotlight. Applebot-Extended is deliberately
#                    absent for the same reason as Google-Extended below: it is
#                    a training opt-out token, not a citation crawler.
#
# !! A named group is read INSTEAD of the wildcard group, not in addition to
# it. Anything added below `User-agent: *` has to be repeated here or it will
# not apply to these bots. That asymmetry is the whole cost of naming them. !!
#
# Google-Extended is deliberately absent. It governs Gemini model training only,
# Google states it is not a ranking signal, and it has no bearing on AI
# Overviews — which are served off the ordinary Googlebot index. Adding it here
# would imply a control it does not have.

User-agent: OAI-SearchBot
User-agent: ChatGPT-User
User-agent: Claude-SearchBot
User-agent: Claude-User
User-agent: PerplexityBot
User-agent: Perplexity-User
User-agent: bingbot
User-agent: DuckAssistBot
User-agent: Applebot
Allow: /

User-agent: *
Allow: /

Sitemap: https://realtimeclipboard.com/sitemap.xml

# ---------------------------------------------------------------------------

# PerplexityBot get a 403 with everything above still saying Allow, and the
# only visible symptom is that the site never gets cited anywhere.
#

# repository can assert it, which is exactly why it is written down.
